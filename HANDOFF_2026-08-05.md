## 🐛 The Vercel env-var bug (in detail)

**Confirmed not a Vercel Hobby limit issue.** Real limits: 1000 env vars per project, 64KB total size, both way over our usage.

**Real issue:** Diagnostic payload shows the function sees 48 env vars at runtime, but **all 48 are Vercel's internal** (`VERCEL_*`, `AWS_*`, `PATH`, `LANG`, etc.). **Zero are user-set.** The 6 env vars in the dashboard (`GEMINI_API_KEY`, `NEWSDATA_API_KEY`, `SUPABASE_*`, `VITE_SUPABASE_*`) are stored correctly but never reach the function.

**Likely cause:** Vercel UI injection bug for "Sensitive" (locked) env vars in some deploys, OR scope mismatch between dashboard and actual function runtime.

**Fixes to try (in order):**
1. Remove the "Sensitive" lock on each env var in Vercel dashboard → save → re-add lock
2. Use Vercel CLI: `vercel env add <KEY> production` then `vercel deploy --prod`
3. File Vercel support ticket with this diagnostic payload (saved to memory for next session)

**Until fixed:** Brief + news + trends soft-fail gracefully to empty states (UI handles them). The salary calc works because of in-code const fallback.

**What I shipped anyway:** All Phase 1.4 (Share card), 2.1 (provenance), and 2.2 (PDF) use **in-code math copies** that don't depend on Vercel env vars. They work today.
