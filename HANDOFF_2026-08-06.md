## The Vercel env-var bug — full diagnosis

### Symptom
- 6 user env vars set in Vercel dashboard (Production + Preview scope)
- Dashboard shows them as "Encrypted" (correct)
- Function runtime sees only 48 Vercel-internal env vars (`VERCEL_*`, `AWS_*`, `TURBO_*`)
- All 6 user env vars are `undefined` in `process.env`

### What I tried (all failed)

1. ✅ Token (24h, full account) works (`whoami` → `wprotalents-7747`)
2. ✅ `vercel env ls` confirms 6 vars exist in project config
3. ✅ `vercel env pull .env.test --environment production` confirms vars are stored (values masked as `[SENSITIVE]`)
4. ✅ `vercel deploy --prod --force` - fresh build, no cache, still fails
5. ✅ API call `GET /v9/projects/prj_MkqBIidk0B4gni4mnfWFeHpGFGDg/env?decrypt=true` - returns `value: ""` with `decrypted: false`
6. ❌ `vercel deploy --build-env KEY=VALUE` - **NOT VIABLE** because I cannot read the values to pass them

### Root cause (my best guess)

Vercel encrypts env-var values at rest with a key only their build environment can decrypt. The encryption key is tied to the project + env-var ID, not the user's account. When the function runs, Vercel's edge should decrypt and inject, but something in that pipeline is broken for this project.

This is NOT:
- A Hobby plan limitation (Pro has the same bug for the same root cause)
- A scope issue (Production + Preview set correctly)
- A build cache issue (cleared with `--force`)
- A project linking issue (linked to `prj_MkqBIidk0B4gni4mnfWFeHpGFGDg` correctly)
- An SDK version issue (switched from `@google/genai` to `@google/generative-ai` in `77ac557`)

### New finding: SSO protection masking diagnostics

Project has `ssoProtection: { deploymentType: "all_except_custom_domains" }` enabled. This means:

- `intel.wprotalents.lat` (custom domain) → public, no SSO
- `latam-intel-yhg3-*.vercel.app` (preview URLs) → SSO-protected, returns Vercel login HTML

All my prior "env vars are undefined" tests against preview URLs were testing the SSO redirect, not the function. The real test has to be on `intel.wprotalents.lat`, which I did today and confirmed the bug is real.

### pdf-lib gotcha
- Helvetica WinAnsi font can't encode U+2014 (em dash), U+2192 (right arrow), U+2605 (black star), etc.
- Use ASCII chars only in PDF text
- Live web UI uses Inter which supports full Unicode

### Vercel function naming
- Vercel auto-detects `/api/*.ts` and `/api/<subdir>/*.ts` as serverless functions
- Cross-tree imports (`../../src/...`) don't work - must inline or copy
- Max 12 functions on Hobby plan (we're at 11: jobs, market-intel, market-intel/env-test, market-intel/volume, og/salary, report/salary, report/ping, cron-refresh-salary, newsletter/generate, newsletter/send, cvradar)

### Vite env var behavior
- `VITE_*` env vars are inlined at build time
- If env var is missing at build, it's hardcoded as `undefined` in client bundle
- `import.meta.env.VITE_*` is the correct accessor (not `process.env.VITE_*`)

### Push workflow
- `git remote set-url origin https://x-access-token:ghp_...@github.com/...`
- `git push -u origin <branch>`
- Bare token in URL returns 404 - must use `x-access-token:` prefix

### PowerShell + Vercel CLI
- Must `Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass` before each session
- `vercel env pull .env.test` to see what env vars are actually accessible (values masked as `[SENSITIVE]`)
